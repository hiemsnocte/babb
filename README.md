# babb

오늘의 급식 메뉴를 자동 캡처하고, 메뉴 이미지·JSON을 GitHub Pages에 정적으로 배포하는 프로젝트입니다.

## 메뉴 중심 화면

방문자는 `public/data/menus.json`과 같은 사이트의 이미지 파일을 읽습니다.
메뉴 확인에는 Firebase SDK나 Firestore 연결이 필요하지 않습니다. 자동화가
캡처를 끝낸 뒤 `scripts/prepare-site.cjs`가 기존 Firestore 메뉴 문서를 한 번 읽고,
등록된 식당의 캡처 이미지와 고정 메뉴 사진이 모두 정상인지 확인한 후 정적 배포 파일을 만듭니다.
이미지 파일명에는 내용 해시를 사용해 같은 이미지를 재사용합니다.

메뉴가 일부 누락되거나 이미지 준비에 실패하면 배포를 중단해 기존 사이트를
보존합니다. 브라우저도 마지막으로 불러온 정상 메뉴의 정보를 저장하며, 새 조회나 새 이미지
로드가 실패했을 때 이미 표시된 메뉴를 지우지 않습니다. 브라우저 저장소에는 이미지 주소를
저장하므로 새 배포에서 이전 이미지가 사라진 뒤 새 JSON 조회도 실패하는 경우까지
이전 사진 복원을 보장하지는 않습니다. 카드는 검은 제목 띠와
사진 테두리를 붙인 형태이며, 모든 메뉴의 사진 영역을 4:3으로 통일해 카드 높이를 맞춥니다.
가로 사진은 영역에 맞춰 세로로 늘려 표시하고, 세로 메뉴는 비율을 유지해 양옆에
여백이 남습니다. 사진을 자르지는 않으며 확대·비교에서는 원본 비율로 볼 수 있습니다.
벽산 메뉴의 양옆은 사진에 맞춰 흰색으로 표시하고, 제목 띠와 바깥 테두리는 검은색을 유지합니다.
날씨·갱신일 위치와 문구를 유지합니다. 이미지 확대·크기 조절·비교·드래그 정렬도
원본 UI 모듈에서 그대로 제공합니다. 새 경고 문구나 별도 참여 화면은 추가하지 않습니다.

PC에서는 상단 날짜·시간 아래의 보기 버튼으로 1열·2열·3열을 고릅니다. 기본은 2열이며
선택은 브라우저에 저장합니다. 화면 폭 900px 이하에서는 1열로 표시하고 PC 폭으로
돌아오면 이전 선택을 복원합니다. 보기 변경은 메뉴를 다시 받거나 참여 연결을 늘리지 않습니다.

날씨도 자동화에서 구로 지역의 3일 시간별 예보를 한 번 받아 저장합니다.
브라우저는 저장된 예보에서 현재 한국 시간에 맞는 값을 고릅니다. 날씨 API가
실패해도 메뉴 배포는 진행합니다. 날씨 조회 상태는 메뉴 표시에 영향을 주지 않습니다.

## 전광판과 이모지 투표

전광판은 기존처럼 메뉴 이미지 위에 자동으로 흐릅니다. 카드를 누르면 기존 위치에
이모지 7개와 `+한마디`, `메뉴만 보기`가 나타납니다. Firebase 초기화는 메뉴가
먼저 표시된 다음 시작하므로 참여 기능의 장애가 메뉴 조회를 막지 않습니다.

식당별 결과 문서는 처음 한 번 읽고, 메시지만 최근 10개로 제한해 실시간 구독합니다.
댓글 리스너는 식당별 최대 1개(현재 4개)이며, 메뉴 갱신이나 카드 재클릭으로 늘어나지
않습니다. 목록에서 빠진 식당의 연결도 정리합니다. 백그라운드 탭에서는 잠시 후
구독을 멈추고 다시 화면을 보면 재연결합니다.

- 투표: 기존 이모지 7개로 반복 참여할 수 있으며 연타만 3초 간격으로 제한합니다.
  트랜잭션으로 결과를 읽고 한 번 씁니다. 경합으로 재시도되면 읽기 횟수는 늘어날 수
  있습니다. 투표 결과 문서는 실시간 구독하지 않아 모든 방문자에게 쓰기마다 읽기를
  발생시키지 않습니다. 읽어온 오늘의 결과는 3표라면 `😍 😍 😍`처럼 투표 수만큼
  이어지는 열차로 메시지와 번갈아 지나가며, 본인의 투표 결과는 성공 즉시 표시합니다.
  긴 열차는 화면에 걸친 이모지 칸만 재사용해 표 수만큼 화면 요소를 생성하지 않습니다.
  다른 사람의 최신 투표는 페이지를 새로 열거나 본인이 투표할 때 읽습니다.
- 전광판: 메시지 120자, 30초 간격. 성공한 메시지는 해당 화면에 즉시 반영하며
  추가 조회하지 않습니다. 다른 사용자의 새 메시지도 전광판에 자동으로 반영합니다.
- 묘지는 화면에서 제거했습니다. 게임 물리나 합체·희생 계산에서 발생하던 자동
  Firestore 쓰기는 없습니다.
- 전송 간격은 브라우저에서 연타를 줄이는 장치입니다. 저장소를
  지우거나 직접 API를 호출하는 사용자를 막지는 않습니다. 운영 Firestore 보안
  규칙·App Check는 별도로 관리해야 하며 이 저장소에서 배포하지 않습니다.

메뉴 자체와 날씨는 방문자 수와 무관하게 원본 API를 추가 호출하지 않습니다.
자동 전광판을 포함한 초기 Firestore 읽기는 식당 4곳·방문자 1,000명 기준
약 8,000~44,000회입니다. 식당 수에 비례해 늘어납니다.
댓글이 없어도 쿼리에는 최소 1회 읽기가 적용됩니다. 새 메시지 전달과 재연결에는
추가 읽기가 발생합니다. 이미지 트래픽은 GitHub Pages에 발생하므로 방문량이 늘면
월간 대역폭을 확인해야 합니다.

## 식당 추가

화면 순서와 식당 정보는 `public/restaurants.json`에서 관리합니다. 메뉴 표시·비교와
댓글 정리는 이 목록에 맞춰 동작하며 식당 3곳으로 제한하지 않습니다. 식당 ID는
투표·댓글의 저장 경로이므로 이름이 바뀌어도 같은 식당의 ID는 유지하세요.

생앤맥주판(`beerpan`)은 `public/assets/menus/beerpan.png`를 계속 표시하는 고정
메뉴입니다. 식당 이름 오른쪽에 인스타그램과 당근 링크를 제공하며 두 사이트의
게시물은 자동 수집하지 않습니다.

식당 설정의 `priceWon`은 이름 옆에 원화 가격으로 표시합니다. `closedDays`는
0(일요일)부터 6(토요일)까지의 요일 배열이며 사진 오른쪽 위에 정기 휴무 배지로
표시합니다. 현재 봄봄에 `[0]`을 등록해 `휴무: 일요일`을 검은 테두리·어두운 빨강 배경·흰 글씨로 표시합니다. 가격과 휴무는 자동 추출하지 않는
수동 정보입니다. 좁은 카드에서는 이름·가격의 중앙 정렬을 유지하도록 소식 링크를
제목 영역의 다음 줄 오른쪽에 표시합니다.

고정 메뉴 식당을 추가하려면 `public/assets/menus/`에 사진을 넣고 목록에 다음
형식의 항목을 추가한 뒤 `npm run prepare:site`로 발행 파일을 만듭니다.

```json
{
  "id": "new-restaurant",
  "name": "새 식당",
  "source": { "type": "static", "path": "./assets/menus/new-restaurant.jpg" },
  "links": [{ "label": "인스타그램", "url": "https://www.instagram.com/example/" }]
}
```

매일 자동 수집할 식당은 `source: { "type": "capture" }`로 등록하고,
`capture.js`에도 해당 식당의 수집 규칙을 추가해야 합니다. 캡처 결과 문서에 같은
ID의 메뉴가 있어야 발행됩니다. 고정 메뉴 식당은 캡처 코드나 Firestore 메뉴 문서를
수정할 필요가 없습니다. 모든 메뉴를 검증한 후에만 발행 파일을 교체합니다.

## 게임 원형 보관

`archive/interactive-v1/`에 최적화 전 HTML·JS를 원본 그대로 보존했습니다.
핀볼, 왕관·합체, 콤보, 묘지와 전광판 효과를 향후 다른 게임에 가져갈 수 있습니다.
이 폴더는 배포 대상이 아닙니다. 재사용 안내는 해당 폴더의 README를 참고하세요.

## 로컬 화면 확인과 검증

```sh
npm ci
npm test
npm run prepare:site
npm run preview
```

`http://127.0.0.1:4173`에서 화면을 확인합니다. `prepare:site`는 공개 메뉴 문서,
메뉴 이미지와 날씨를 읽고 로컬 `public/data/`에만 파일을 만듭니다. 생성 파일은
Git에 넣지 않습니다. 공개 Firebase 설정은 `public/config.json`에 있으며,
게시 스크립트에서는 `FIREBASE_PROJECT_ID`, `FIREBASE_API_KEY` 환경변수로 덮어쓸 수 있습니다.

```sh
npx puppeteer browsers install chrome
npm run test:browser
```

브라우저 검증은 로컬 모의 서버·Firebase 모의 응답으로 실행해 운영 데이터에 쓰지
않습니다. 기본 `npm test`는 브라우저 설치 없이 실행할 수 있습니다.

## 로컬에서 캡처 봇 실행 (자주 까먹을 때 여기만 보기)

1. **의존성 설치** (처음이거나 `package-lock.json`이 바뀐 뒤)

   ```bash
   npm ci
   ```

   또는

   ```bash
   npm install
   ```

2. **`.env` 파일**을 프로젝트 루트에 두고, `capture.js`가 요구하는 값을 채웁니다.  
   (`FIREBASE_*` 전부 + `GITHUB_TOKEN` — repo 쓰기 권한이 있는 PAT)

3. **캡처 실행** (이게 본 명령)

   ```bash
   node capture.js
   ```

4. **Chromium이 없다는 오류**가 나면 (선택)

   ```bash
   npx puppeteer browsers install chrome
   ```

   CI나 특정 환경에서는 `PUPPETEER_EXECUTABLE_PATH`로 브라우저 경로를 지정할 수 있습니다.

성공 시 로컬에 `menu_*.png`가 생기고, 원격 `menus` 브랜치와 Firestore `menus/current`가 갱신됩니다.

## 기타

- 정리 스크립트(이모지/댓글 일일 정리): `node cleanup.js` (같은 `.env`의 Firebase 변수 필요)
- 자동 실행: `.github/workflows/main.yml`(캡처·Pages), `cleanup.yml`(정리)
